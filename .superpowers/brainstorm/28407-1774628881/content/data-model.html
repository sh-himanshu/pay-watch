Pay-Watch — Data Model

Supabase Postgres schema — core tables and relationships

Database Schema
users
Managed by Supabase Auth
id uuid PK
email text
name text
avatar_url text
created_at timestamptz
email_accounts
Connected email providers
id uuid PK
user_id uuid FK → users
provider enum (gmail, outlook...)
email_address text
access_token text (encrypted)
refresh_token text (encrypted)
last_sync_token text
last_synced_at timestamptz
is_active boolean
billers
Known companies that send bills
id uuid PK
user_id uuid FK → users
name text
sender_email text
category enum (utility, subscription...)
typical_amount numeric
billing_cycle enum (monthly, yearly...)
first_seen_at timestamptz
bills
Individual parsed bill/payment entries
id uuid PK
user_id uuid FK → users
biller_id uuid FK → billers
email_message_id text
amount numeric
currency text default 'USD'
due_date date
status enum (pending, paid, overdue)
parsed_by enum (rule, ai)
confidence numeric
raw_subject text
raw_snippet text
detected_at timestamptz
alerts
Fee anomalies and payment reminders
id uuid PK
user_id uuid FK → users
bill_id uuid FK → bills (nullable)
type enum (price_increase, unexpected_charge, new_biller, payment_due, overdue)
severity enum (info, warning, urgent)
title text
description text
is_read boolean
is_dismissed boolean
created_at timestamptz
notification_preferences
Per-user notification settings
id uuid PK
user_id uuid FK → users
push_enabled boolean
email_digest_enabled boolean
digest_frequency enum (daily, weekly)
push_subscription jsonb
notify_on_due boolean
notify_on_price_change boolean
notify_on_new_biller boolean
due_reminder_days int default 3
Relationships
users 1 → N email_accounts (one user, multiple providers later)
users 1 → N billers (billers are per-user for personalized tracking)
users 1 → N bills
billers 1 → N bills (each bill belongs to a biller)
bills 1 → N alerts (a bill can trigger multiple alerts)
users 1 → 1 notification_preferences
